# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Marketing landing page for **Root** (brand "OKRoot") — a personalized-nutrition
app for celiacs, diabetics, and lactose-intolerant users. Spanish-language copy.
Static **Astro** site, deployed to Netlify at the `okroot.co` domain root.

## Commands

```bash
npm run dev       # Astro dev server (http://localhost:4321)
npm run build     # astro build → static HTML in dist/
npm run preview   # serve the production build locally
npm run lint      # astro check — TypeScript + .astro type-check; THIS IS THE "lint"
```

There is no ESLint, Prettier, or test runner. "Linting" means `astro check`
(TypeScript + template type-checking). Verify changes with `npm run lint` or
`npm run build`. Note: `@tailwindcss/vite` is typed against a different Vite
version than Astro's bundled one, so its plugin is JSDoc-cast to `any` in
`astro.config.mjs` to keep `astro check` clean — leave that cast in place.

## Architecture

- **Routing is file-based** (`src/pages/*.astro`). Each file is a real static
  page: `index` → landing, plus `sobre-mi`, `contacto`, `preguntas`, the four
  legal pages (`privacidad`, `terminos`, `habeas-data`, `cookies`), and `404`.
  Every route is its own prerendered HTML file — there is no SPA fallback or
  redirect. Astro's `<ClientRouter />` (View Transitions, wired in `Base.astro`)
  is layered on top purely as progressive enhancement: it crossfades between
  those real HTML pages, so client scripts must re-run on `astro:page-load`, not
  just initial load. The landing (`src/pages/index.astro`) composes section
  components in
  fixed order (`Hero → PainSection → HowItWorks → Comparison → Features →
  Founder → Pricing → Waitlist → FaqSection`).
- **Recipes are a content collection**, not pages. `src/content/recetas/*.md`
  feed a `glob`-loader collection defined in `src/content.config.ts`; its Zod
  schema validates every recipe's frontmatter at build (`astro check` fails on a
  bad recipe, so nothing broken ships). `src/pages/recetas/index.astro` renders
  the editorial index (one `destacada` recipe as hero, the rest grouped by
  `categoria`) and `src/pages/recetas/[slug].astro` prerenders one page per
  recipe. Recipe copy follows the same UI copy rules below — notably no medical
  claims (`beneficios` points must cite a verifiable `fuente`/`fuente_url`).
- **`src/layouts/Base.astro`** wraps every page: it owns the `<head>` (SEO meta,
  canonical, Open Graph/Twitter tags, site-level JSON-LD, self-hosted fonts via
  `astro:assets` `<Font>`, `<ClientRouter />`, and `<Analytics />`) plus the
  shared `<Header>` / `<Footer>`, the `<CookieBanner />`, and the
  reveal-on-scroll script. Pages pass `title`, optional `description`,
  `ogTitle`/`ogDescription` overrides, `ogImage` (defaults to `/og.png`), and
  `noindex`. Extra JSON-LD lives where it's page-specific: `Recipe` schema in
  `recetas/[slug].astro`, `FAQPage` schema in `FaqSection.astro` /
  `preguntas.astro`. The sitemap is auto-generated by `@astrojs/sitemap` (wired
  in `astro.config.mjs`, emits `sitemap-index.xml`, excludes `404`) — there is
  no hand-maintained `public/sitemap.xml`.
- **Reveal-on-scroll animations**: add the `reveal` class to elements; a small
  `IntersectionObserver` script in `Base.astro` adds `is-visible` when they enter
  view. It re-runs on every `astro:page-load` so reveals work after View
  Transition navigations too. Stagger children with an inline `--reveal-delay`.
  All animation is pure CSS — do not add an animation library.
- **Icons** are inlined at build by **astro-icon** (wired in `astro.config.mjs`),
  pulling from the `@iconify-json/lucide` set — e.g.
  `<Icon name="lucide:..." />`. They emit inline SVG (no runtime JS), so they
  satisfy the "use a real icon, never an arrow glyph" copy rule below and the
  strict `script-src 'self'` CSP.
- **Analytics & cookie consent**: GA4 (`Analytics.astro`) is consent-gated and
  never loads by default. `CookieBanner.astro` owns the consent UI and the
  `okroot_cookie_consent` cookie; on accept it calls `window.okrootLoadGA4()`,
  which injects gtag.js using the `PUBLIC_GA_ID` measurement ID. When `PUBLIC_GA_ID`
  is unset (local dev, previews) nothing loads. Both are bundled `<script>`s
  (hashed `/_astro/*.js`), so no `'unsafe-inline'` is needed.
- **Components** are `.astro` files in `src/components/`. They render to static
  HTML at build time; interactive bits use plain `<script>` blocks (Astro
  bundles them to hashed `/_astro/*.js`).

## Styling

- **Tailwind CSS v4, CSS-first config** via the `@tailwindcss/vite` plugin (wired
  in `astro.config.mjs`) — there is no `tailwind.config.js`. The theme lives in
  `src/index.css` under `@theme { ... }` (brand colors like `--color-primary`,
  fonts, easing). Extra design tokens are plain CSS vars on `:root`. Add/adjust
  tokens there, then use them as Tailwind utilities (e.g. `bg-primary`,
  `text-accent`, `border-line`).
- Path alias `@/` → `src/`, configured in **both** `astro.config.mjs` (Vite
  `resolve.alias`, needed at build time) and `tsconfig.json` (`paths`, for the
  type-checker).

## UI copy rules

Hard rules for anything rendered to the user (visible text, button labels, page
`<title>`s, `aria-label`s):
- **Never hardcode arrow characters** (`→`, `←`, `➔`, …) in buttons or copy. If a
  control needs a directional affordance, use a real icon (an inline SVG / icon
  component), not a glyph in the text.
- **Never use the em-dash `—` in UI text.** Use a comma, colon, period, or `·`
  separator instead. (Code comments are exempt — this is about rendered copy.)
- **All routes and content are Spanish.** Page slugs included (`/preguntas`,
  `/contacto`, `/sobre-mi`, `/privacidad`, `/terminos`, `/habeas-data`,
  `/cookies`, `/recetas`). An English version comes later as a separate locale —
  do not mix languages into these pages.
- **No tech-stack name-drops in marketing copy** (Django, React, Claude API, PWA,
  etc.) — they don't help the user. Describe the benefit, not the stack.
- **No medical claims.** Root is a tool, not a medical/diagnostic device (no
  such permits). Avoid "herramienta médica", "diagnóstico", "tratamiento", etc.

## Configuration constants

`src/lib/consts.ts` holds the runtime-config constants — edit these, not
scattered literals:
- `APP_URL` — where the "Entrar a la app" CTA points (`https://app.okroot.co`).
- `PORTFOLIO_URL` — founder social-proof link (`https://wavival.dev`).
- `EARLY_ACCESS_SPOTS` — early-access scarcity count on the waitlist. Must be a
  real number; set to `0` to hide the scarcity line.
- `PRICING` — the Free + Pro model rendered by `Pricing.astro`. `free` is the
  permanent free tier (`beneficios` list); `pro` is the paid plan (`pruebaDias`
  free-trial length, `mensual` / `anual` in COP + approx USD, `ahorroPct` on
  annual, and the `extra` list shown above "Todo lo de Gratis, y además:").
  Edit these numbers/lists and the Pricing section updates itself; keep all copy
  free of medical claims and tech-stack names. The Pro card's monthly/annual
  toggle is a small `<script>` flipping `data-billing` (CSS shows the active
  price).

The waitlist form posts to **Supabase**. `src/components/Waitlist.astro` inserts
into the `okroot-waitlist` table via PostgREST (no SDK — plain `fetch`, zero
bundle cost) using `PUBLIC_SUPABASE_URL` / `PUBLIC_SUPABASE_ANON_KEY`. Astro only
exposes env vars prefixed `PUBLIC_` to client scripts. When either var is
missing the form runs in **optimistic-demo mode** (logs, no network) — so
**production builds on Netlify must have both env vars set**, or signups are
silently dropped. The anon key is public by design; Row Level Security
(`supabase/waitlist.sql`: anon may INSERT only) protects the data. The CSP in
`netlify.toml` already allows `connect-src https://*.supabase.co` (plus the
Google Tag Manager / Analytics origins used by GA4).

GA4 reads one more public env var, `PUBLIC_GA_ID` (the `G-XXXXXXXXXX`
measurement ID). It's optional: leave it unset and no analytics script ever
loads. See `.env.example` for both Supabase and GA4 vars.

## Deploy (Netlify)

`netlify.toml` is the source of truth: build → `dist`, strict security headers
including a tight CSP, and immutable caching for hashed `/_astro/*`. The site
serves at the domain root (`site: "https://okroot.co"` in `astro.config.mjs`).
There is no SPA redirect — Astro emits a real HTML file per route, and Netlify
serves `404.html` for unknown paths.

Set `PUBLIC_SUPABASE_URL` / `PUBLIC_SUPABASE_ANON_KEY` in Netlify env vars (Site
settings → Environment variables) and run `supabase/waitlist.sql` against the
project, or the production waitlist form silently drops signups (see
Configuration constants above).
